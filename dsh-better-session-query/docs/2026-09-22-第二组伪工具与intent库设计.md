# 第二组伪工具与 intent 库：设计讨论

- 时间：2026-09-22
- 场合：从「归档会话里的伪工具调用会被遗忘」这个缺口聊出来的
- 相关代码：`D:\dev\SAC_search\dsh-better-session-query`（lib/index.js、lib/memory.js、lib/store.js、lib/indexer.js）

## 一、现状：双索引

**块索引**（`lib/store.js`）：全量派生、随时可重建、十九万块量级。表是 `block_meta` / `block_text` / `block_fts` / `indexed_sessions`。

**记忆库**（`lib/memory.js`）：独立的小库，`memory` + `memory_fts`。字段 `block_id / session_id / cwd / seq / time / surface / q / a / tag / expires / perspective / qa`。

为什么分开（文件头写的）：块索引是全量派生、随时可重建的；记忆是稀疏的、要按关键词召回、还要按新鲜度分层。放同一个库里，记忆查询会被十九万块的倒排拖着走，动一次 schema 还要连带迁移块索引。独立之后，块索引重建不影响记忆，记忆库损坏也不影响检索。

关系是**派生**：伪工具自己不存任何东西，调用参数作为 tool-call 块进会话日志；索引器抽块时顺路解析出来写进记忆库。真相源是会话日志，**删库重建 = 重跑一遍索引**。

## 二、归档缺口

`includeArchived` 默认 false。归档会话不进索引，而且**已经在索引里的会被清掉**（`indexer.js` 的 `purge.push(item.id)` 推的是会话 id，走块索引按 `session_id` 删）。记忆库的删除是按 `block_id` 的块级操作，**所以归档不碰记忆库**。

但有个缺口：**从没被索引过就被归档的会话**，因为「归档的连日志都不读」，它的记忆从来没进过记忆库。这种情况下「搜不到」和「没记过」分不开。

归档本身不是丢：日志原地不动，`listSessions()` 照样列，取消归档后下一轮自然回来；`includeArchived` 打开也能连归档一起搜。

## 三、遗忘（forgeted）—— 与过期是两回事

**过期**：`expires` 是描述性文本（「换了项目就作废」），界面显示成「失效于 …」，**recall 不拿它过滤**。

**遗忘**：很重的操作。做法是**确确实实重写 session** —— 给那条已存在的伪工具调用**添加一个 agent 无法添加的属性**。

- 为什么 agent 加不了：伪工具的 schema 是 `additionalProperties: false`，它写不出这个字段；execute 又什么都不做。
- 为什么必须重写而不是追加：追加的话 agent 也能 append，它就能自己遗忘自己。**重写 = 只有能改文件的人才能做**，遗忘的权限天然等于改文件的权限。
- 标记之后：**人类用户还能看到**；**agent 除非用 SQL，否则召回不到**。块索引里那条还在，记忆库的**召回面**排除它 —— 遗忘不是销毁，是不再主动浮现。

实现上要当心：会话日志本来只有追加语义，直接改一条已有事件要保证还能被正常重放（格式版本、校验、改坏了怎么回滚）。

## 四、intent 库（第二个派生库）

用来装任务列表。**读的语义跟 memory 根本不同**：

| | memory | intent |
|---|---|---|
| 读的方式 | 关键词召回 | 取 fold 结果 |
| 新鲜度 | 有（默认 2 小时分层） | 无 |
| 权重 | 有（字面相关性 × 新鲜度） | 无 |
| 结果 | 「可能相关的几条」 | 「就是这些，完整」 |
| 漏一条 | 正常（想不起来） | bug |

所以命名上跟 `memory` 成对：memory 是「我知道的」，intent 是「我要做的」。不用 `task` / `todo`，因为会跟 DSH 的 `todo_write`（会话内待办）和 Agent Teams 的 `team_task_create`（共享任务板）撞。

**悬置的点子留在 memory，不进 intent** —— intent 没有「模糊」那一层来挡住它，一条未决的点子进了 intent 就会出现在任务列表里，而悬置的意思恰恰是「先别在日常视野里」。

## 五、任务列表 = 时间序列叠加

- 不存「当前列表」，存**变更指令**；当前列表是指令按时间 fold 出来的结果（事件溯源）。
- 每条指令作为 tool-call 块留在它发生的那个会话里 → **能追踪哪一条是哪个会话改的**。
- 但**看任务时只看到叠加完成之后的结果**。
- 同样不落文件系统，纯靠日志考古；任务库坏了不该影响检索。
- 删除用 **tombstone**，不能真删（否则历史没法重放）；fold 到墓碑就把那条从结果里拿掉。

**待定**：id 谁来生成。伪工具的 execute 什么都不做，没法像普通工具那样分配 id，而增量指令必须能指认「改的是哪一条」。可能的做法：调用方生成、规则简单可预测（如 `t-20260922-a3f`），并规定幂等（同 id 再 add 当 update）。
