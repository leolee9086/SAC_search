# 记忆空闲提醒规则 memory-idle（2026-09-27）

需求（哥哥）：**15 分钟内没调用过记忆工具，就提醒模型"有重要的事要记一下，并且记的时候注意标签等"。**

## 加在哪

`lib/notice-rules.js` 的 `NOTICE_RULES`（那是它的源码，本包没有 `src/`）。
规则是**纯数据**，由 context-care 取走、接进规则引擎、命中后注入 —— 本插件不判断谁该提示。

```js
{
  id: "memory-idle",
  order: 20,                 // 比 memory-remember-request(10) 大：用户明说「记住」时先让那条赢
  placement: ["user"],       // 提醒发生在"用户刚说话"那一刻，不打断助手自己的输出
  when: { idle: { since: "session_blocks_remember", minutes: 15 } },
  action: { kind: "notify", by: "context-care", say: "…" },
  cooldownMinutes: 15,
  oncePerSurface: true,
}
```

## 两个必须知道的引擎语义

1. **`idle` 在「从来没调用过这个工具」时不命中**（规则引擎 README 明写）——
   否则所有提醒类规则会在会话开头一起响。
   ⇒ **新会话里如果一次都没记过，这条不会触发**；只有"记过、然后 15 分钟没再记"才触发。
   如果要"从没记过也提醒"，得改引擎语义，或者在 `when.said` 上另写一条兜底 —— **目前不做**。
2. **`idle` 的条件是「距离上次*记东西*多久」，不是「距离上次*提醒*多久」** ——
   15 分钟一过**每一轮请求都满足**。所以 `cooldownMinutes: 15` 不是可选项：
   没有它，这条规则会每轮都响一次。

## 提醒正文覆盖的点（测试按点断言）

- 已经 15 分钟没记东西了；
- 回头找：踩过的坑 / 定下来的约定 / 临时结论 / 人的偏好；
- **q** 写成以后真会拿来搜的措辞（索引是连续子串匹配，换说法就搜不到）；
- **a** 只写结论不写过程；
- **tag** 给一两个检索用关键字（环境/约定/踩坑/人），是检索标签不是分类；
- **perspective** 三选一（superego / ego / id），凭感觉标；
- 出口：确实没有值得记的就跳过，**不要为了回应提醒硬凑一条**。

## 验证

```sh
node test/notice-rules.test.mjs    # 6 passed（新增 2 条：idle 的形状与措辞、两条规则的先后）
```

新增的两条断言：`when.idle` 精确等于 `{ since: 'session_blocks_remember', minutes: 15 }`、
`cooldownMinutes === 15`、正文里四个要点都在、出口句在；以及 `memory-remember-request.order < memory-idle.order`。

## 生效

**宿主侧插件，没有 HMR —— 改完要重启 DSH。** 重启后这条规则才会被 `ctx.provide` 交出去。
（consumer 侧那两条 collect 接线已经在同一轮里恢复，见 dsh-context-care 的对应笔记。）
